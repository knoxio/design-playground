# PRD-07 — Handoff package

**Status:** Built
**Owns:** C14 (handoff package generation)
**Depends on:** PRD-02 (the token schema is what gets exported), PRD-04 (the chosen experiment is what gets handed off)
**Governing ADRs:** [0001-one-app-clients-as-folders](../adr/0001-one-app-clients-as-folders.md), [0006-experiments-variants-graduation](../adr/0006-experiments-variants-graduation.md), [0014-claude-only-authoring](../adr/0014-claude-only-authoring.md)

## Problem

The engagement's exit artifact is what engineers build the real product from.
Without a defined package, handoff is "read the prototype repo and guess," and
the highest-risk gap — what in the prototype is illusion — stays implicit. The
prototype is reference, never the shipping artifact, so tokens and the component
inventory must transfer 1:1 even though prototype code does not.

## Design

### Mechanics in the script, judgment in the skill

The deterministic artifacts are generated by `pnpm handoff <id>`
(`scripts/handoff.mjs`) — reproducible, testable, runnable by a human with no
Claude session. The `/handoff` skill drives that script and owns only the
judgment artifacts (PRD finalization, the real-vs-mocked review). This is the
repo-wide rule: mechanics in scripts, judgment in skills, skills call scripts.

### The package — `clients/<id>/handoff/`

1. **`prd.md`** — the client PRD finalized: every `assumed`/`open` item resolved
   or explicitly carried into an "Open engineering questions" section, statuses
   removed, no playground jargon (variant, graduation) without a one-line gloss.
   The skill refuses to run quietly over unresolved items — it lists every
   `assumed`/`open` PRD item and every still-`active` experiment (handoff exports
   Main only, so an undecided experiment's work vanishes unless surfaced) and
   makes Mary resolve or consciously carry each one.
2. **`tokens.json`** — the chosen design system as a W3C DTCG token document, so
   engineers pipe it straight into their own tooling. Playground concepts export
   resolved (density becomes a real spacing dimension); anything truly
   non-standard rides `$extensions`. No Style Dictionary in the playground.
3. **`components.md`** — inventory of every component the chosen experiment and
   Main pages use: kit components (name, props used) and client components
   (source path, what they do, promotion-candidate flag). Import-based, so it can
   over-report (kit usage inside a client component counts like page usage) and
   under-reports by design (experiments excluded) — the skill corrects what it
   can verify and adds the "what it does" context for client components.
4. **`real-vs-mocked.md`** — the illusion list: mock-data sources, absent
   auth/permissions, instant fake latency, missing error/empty/loading states,
   anything interactive that does not persist. Generated from conventions plus a
   prompted review, then edited by Mary — never shipped unreviewed. With no
   reviewer in the session it is stamped `DRAFT — PENDING REVIEW` and the commit
   message says so.
5. **`screens/`** — chrome-less full-page screenshots of every page of the
   chosen experiment and Main pages (`playwright-core` driving the locally
   installed Chrome, so no browser download enters the dependency tree). The
   skill confirms each shows only the product canvas.

### Addendum mode

`/handoff --addendum <exp-id>` produces a one-page delta for support-period
changes — what changed, new tokens/components, updated real-vs-mocked entries —
instead of regenerating the whole package.

## Behavior / acceptance

1. `/handoff demo` produces all five artifacts; an engineer who has never seen
   the playground can state what to build, with which visual tokens, and what not
   to trust from the prototype.
2. Unresolved PRD items and still-active experiments block silent completion.
3. The package is self-contained — no links back into playground internals other
   than the client folder itself.

## Non-goals

- Pushing anything to the engineers' repo — handoff is a folder they pull from,
  one-directional.
- Code export or transformation of prototype pages — the prototype is reference,
  explicitly not the shipping artifact.
